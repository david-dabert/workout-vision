  **Defect 1 (main): the change still wins after `hashchange` has fired but before React has rendered it**
  
  - **Where:** `/home/user/workout-vision/src/App.jsx:130`, where `stale()` is `ticket !== waiting.current || pageRef.current !== from || browserMoved()`. The helper is at `/home/user/workout-vision/src/lib/useHashRouter.js:36` (`known.current = next;` in `onHashChange`) and line 57 (`browserMoved`).
  - **Mechanism:** `onHashChange` sets `known.current = next` and calls `setPageState(next)`.
    - `hashchange` is a native event, so React 19 gives it default priority and renders it in a later scheduler task.
    - Until that render, `browserMoved()` is false (`readHash() === known.current`).
    - `pageRef.current` is still `from`, because it is only updated in a layout effect after the render.
    - `ticket` has not changed.
    - So `stale()` returns false for that whole stretch.
  - **What goes wrong:** any waiting `show()` or View Transition update that runs in this stretch goes ahead. It calls `setPage(next)`, which writes `location.hash = next` (a new history entry), and in the transition path `flushSync` then applies both queued updates, ending on `next`. The browser's navigation is undone. That breaks the goal of the change.
  - **Concrete scenario (iPhone Safari, slow first load of a chunk):**
    1. On the choice screen, tap a lift card. The Film chunk is not loaded yet, so the change waits on `warm().then(show)`.
    2. Swipe back to `#exercises`. `hashchange` fires.
    3. The Film chunk's load resolves before React's render task runs.
    4. Result: the filming screen appears and the URL is rewritten to `#film`.
  - **Same scenario, loaded chunk:** with Film already loaded, the View Transition update callback runs at the next rendering opportunity. That can fall between the `hashchange` task and React's render task, which is the flake described in the spec header.
  - **Why the tests miss it:** `e2e/navigation-race.spec.js:27` runs `window.__heldUpdate()` in the same task as `location.hash = ...`, before `hashchange` is dispatched. The first test's `evaluate` at line 27 exercises only the first half of the stretch.
  - **Smallest failing test:** a copy of the first test in `/home/user/workout-vision/e2e/navigation-race.spec.js` with line 27 replaced by the line below. The extra listener is added after the app's own, so it runs right after `onHashChange` and before React renders.
