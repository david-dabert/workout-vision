**2. Resume check skips missing clips, which are then recorded with a false reason** (`/home/user/workout-vision/scripts/public/fetch-countix.sh:31` and `:33`)
- Val and train clips of one class are extracted into the same folder, `videos/$cls`. Line 31 compares the file count of that folder (both splits) with the size of one split's list.
- Line 33 ends in `|| true`, so a cut or failed curl stream looks the same as the expected tar "Not found in archive" errors.
- Scenario: first run, push up. Val extracts 40 clips, then the train stream is cut after 80 of 115 clips (network drop or Ctrl-C). On the rerun the train check sees 120 ≥ 115 and skips the train tar for good. The val check on any rerun is also always satisfied once train is present.
- The 35 missing sets then reach `sets.json` as "its video is not in the Kinetics mirror", which is not true.
- A clip truncated mid-stream is also counted and kept. It later fails with "the video holds N frames of the M its label spans", which blames the label instead of the download.
- Line 10 has the same weakness: if the labels download is cut, the `countix/` folder exists but is partly written, and a rerun never downloads it again. A truncated last row can become "label not readable" or a shortened count.
- Smallest failing test: a script test with a stub `curl` that serves half of a tar and then exits non-zero, run twice. Expect the second run to request the train tar again, or the manifest reason to differ from "not in the Kinetics mirror". It fails today.
